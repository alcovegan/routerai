# Кассеты записанных ответов RouterAI

Каждый файл — один реальный обмен с `https://routerai.ru/api/v1`. Основная
часть записана 14 августа 2026 года во время аудита SDK, кассеты про роутинг
и алиасы моделей — 3 сентября 2026 года при подготовке 0.4.0. Тела ответов приведены как есть,
включая пробельный «прогрев» перед JSON и SSE-комментарии `: PROCESSING`,
потому что именно эти детали и проверяются.

Кассеты нужны, чтобы поведение SDK на настоящих ответах сервера проверялось
герметично: без сети, без ключа и без расходов. Тесты живут в
`tests/test_cassettes.py`.

## Что урезано

Объёмные поля сокращены, структура сохранена:

- `b64_json` картинки и base64-строка эмбеддинга обрезаны до длины, кратной 4
  (остаются валидным base64);
- числовой вектор эмбеддинга — первые 8 значений;
- base64 входного аудио в теле запроса — первые 64 символа;
- каталог моделей урезан с 458 записей до 8, подобранных так, чтобы остались
  все встреченные способы задавать цену: `prompt`/`completion`, `image_output`,
  `search_units`, `seconds`.

Ключи и заголовок `Authorization` в записи не попадали: сборщик кассет
маскирует их и отказывается писать файл, в котором нашлась строка, похожая
на ключ.

## Формат

```json
{
  "name": "chat_stream_tool_calls",
  "note": "человекочитаемое описание, что в этом обмене важно",
  "finding": "номера находок аудита, к которым относится кассета",
  "recorded_from": "https://routerai.ru/api/v1",
  "request":  {"method": "POST", "path": "/chat/completions", "body": {...}},
  "response": {"status": 200, "content_type": "text/event-stream", "body": "..."}
}
```

## Как пользоваться

```python
from tests.cassettes import cassette_client

client = cassette_client("chat_completion_ok")
result = client.chat.complete("inclusionai/ling-2.6-flash", "привет")
```

`cassette_client` поднимает `RouterAI` поверх `httpx.MockTransport`, который
отвечает телом кассеты. Обращения к сети при этом не происходит — герметичность
дополнительно защищена сетевым гардом из `conftest.py`.

## Когда обновлять

Если RouterAI изменит формат ответов, кассеты станут историческими: они
продолжат описывать поведение на момент записи. Тогда стоит перезаписать их
свежим прогоном и отдельным коммитом, чтобы в истории было видно, что
изменилось на стороне сервера.
